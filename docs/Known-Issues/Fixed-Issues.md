# Fixed Issues

Problems that used to exist and no longer do, with the test that now guards each one. This is the record behind the open lists, so that a regression can be recognized.

> **Scope:** all subsystems
> **Source:** the maintainers' pre-launch and EHNAS fix notes, plus changes visible in the commit history
> **Last verified against:** `ad744e9` (2026-11-03)

I did not re-test these fixes. Test names are taken from the maintainers' notes. Where a fix is a recent commit, the commit is named. If one of these returns, move it back to the matching page and mark it _Open_.

## Parser and PRISM

| Problem                                                          | What users saw                                                                                                                                                                                   | Fix                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PRISM v2 never linked calls to methods.                          | `self.validate()`, `this.step()` and Rust `self.x()` got no edge; every method's `called_by` was empty (950 method nodes with zero incoming edges in the Eulix repository's own knowledge base). | Commit `95f1288` stores the call receiver separately and indexes methods by declared name for **Python, TypeScript and Rust**, resolving `self`, `this`, `cls` and `Self` through the class and its parents. I confirmed on 2026-11-03 that these three now resolve. Go, Java, JavaScript, C and C++ remain open as [PRISM-2](Parser-And-PRISM.md#prism-2-v2-never-links-calls-to-methods-in-go-java-javascript-c-and-c). |
| Calls through unknown receivers could invent edges.              | A uniquely named method was linked by guessing.                                                                                                                                                  | Commit `02f3674` disables that guess. This is the behaviour described in [PRISM-3](Parser-And-PRISM.md#prism-3-calls-on-a-receiver-of-unknown-type-get-no-edge-in-v2).                                                                                                                                                                                                                                                    |
| Rust module paths and JavaScript lookups mis-resolved.           | Wrong targets for `crate::`/`self::` paths and cross-file JavaScript names.                                                                                                                      | Commit `c6acd89`.                                                                                                                                                                                                                                                                                                                                                                                                         |
| Method resolution broke compatibility with older callers.        | Regressions after the receiver work.                                                                                                                                                             | Commit `dcc1633` (restore method resolution compatibility).                                                                                                                                                                                                                                                                                                                                                               |
| `self.x()` in Python was not recognized as an implicit receiver. | The shortcut looked for a `self` parameter that the Python parser removes.                                                                                                                       | Python methods are now treated as having a receiver unless they are static methods (verified: an inherited method in another directory resolves).                                                                                                                                                                                                                                                                         |
| Rust items inside inline `mod` blocks were not extracted (was PARSE-5). | Functions, structs, impls and consts in `mod name { ... }`, including every `#[cfg(test)] mod tests`, had no node; on ripgrep 7,345 of 15,066 call sites sat in functions eulix never saw. | Fixed 2026-11-15: the Rust parser collects items from the file root and every inline module body. On ripgrep v2, correct caller → callee pairs rose from 967 to 1,645. Test `items_inside_inline_modules_are_extracted` (`grammar_files/rust.rs`). |
| Rust `impl` blocks in another file than their type were dropped. | `impl E { ... }` in `other.rs` for a `struct E` in `lib.rs` lost all its methods and their calls; so did `impl Trait for ForeignType`. | Fixed 2026-11-15: such blocks become an `impl_{Type}` entry, and PRISM v2 gives their methods (and `self` inside them) to the type it resolves to. Blanket impls (`impl<P> Tr for &mut P`) are keyed `<P>` so they never bind to a type named `P`. Tests `impl_for_a_type_declared_elsewhere_keeps_its_methods`, `blanket_impls_are_not_keyed_as_a_type_named_like_the_parameter`, `rust_impl_in_another_file_gives_its_methods_to_the_type`. |
| Rust types imported from another crate resolved to the wrong crate's homonym. | `use grep_regex::RegexMatcher; RegexMatcher::new()` linked to a `RegexMatcher` in another crate's `tests/` directory, or in `crates/pcre2`. | Fixed 2026-11-15: files under another crate's `tests/`, `benches/` or `examples/` are never import candidates, and a package directory matching the imported crate name (`grep_regex` → `crates/regex`) is preferred. The earlier test expecting a sibling test target's type was corrected. Tests `rust_type_from_another_crate_skips_that_crates_test_targets`, `rust_imported_crate_name_picks_its_package_among_homonyms`. |
| C++ code in `.h` headers was parsed as C (was PARSE-6). | Classes and inline methods in C++ headers had no node; `class LIB Name : Base {` with an export macro was read as a function `Name`. | Fixed 2026-11-15: a `.h` file with C++-only syntax goes to the C++ parser, and export annotations between `class` and the name are blanked before parsing (offsets unchanged). Tests `cpp_headers_are_told_apart_from_c_headers`, `a_cpp_header_with_the_h_extension_is_parsed_as_cpp`, `export_macros_between_class_and_name_do_not_hide_the_class`. |
| C and C++ skipped everything inside `#if`/`#ifdef` and `extern "C"`. | Every include-guarded header, and any code under a feature `#ifdef`, produced no functions, types or globals. On tinyxml2, 685 call sites targeted methods eulix did not know. | Fixed 2026-11-15: both parsers look through conditional-compilation blocks and `extern "C" { ... }` (both branches of an `#if`/`#else` are kept). On tinyxml2 the unknown targets fell to 26. Tests `items_inside_include_guards_ifdefs_and_extern_c_are_extracted` (`c.rs`), `items_inside_include_guards_and_extern_c_are_extracted` (`cpp.rs`). |
| C++ global variable names included their initializer. | `static int counter = 0;` was recorded as a global named `counter = 0`. | Fixed 2026-11-15: the name is taken from the init declarator's inner declarator. Covered by the C++ include-guard test above. |

## LSP

Found by reviewing PR `bb695d1` (#148) and by the benchmark in `eulix-lsp/bench/`. All of these were re-tested on 2026-11-12. The last four are working-tree changes on `fix/lsp-148-sync` and are not committed yet.

| Problem                                                                                                                       | What users saw                                                                                                                                                                                                                                                             | Fix                                                                                                                                                                                                                                                                                                                                              | Test                                                                                                                                                            |
| ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Indexing was quadratic.                                                                                                       | Each doubling of the workspace made the scan about 4 times slower: 25 s at 4,000 files and 396 s on the Linux kernel. Index requests (cross-file definition, references, workspace search) waited for the whole scan, and every edit and watcher event paid the same cost. | `Index::index_file` checked each new call site against every call already recorded for that name (`sites.contains`). It now removes duplicates within the file with a `HashSet`; `remove_file` already clears the file's old entries. Scan time: 0.41 s at 4,000 files, 49 s on the kernel. See [LSP Indexing](../Architecture/LSP-Indexing.md). | `call_sites_are_deduplicated_and_sorted`, `same_call_line_in_two_files_is_kept_and_reindex_does_not_duplicate`; `bench/bench_lsp.py` growth exponent about 1.0. |
| Open buffers were overwritten when the editor encoded the URI.                                                                | With VS Code on Windows, or paths with `+`, the scan and watcher replaced an open buffer's symbols with the disk version.                                                                                                                                                  | `commit_disk_batch` and `forget_disk` check whether a file is open by comparing paths (`Documents::open_paths`) instead of rebuilding the URI.                                                                                                                                                                                                   | `disk_events_skip_open_buffers_with_client_encoded_uris`.                                                                                                       |
| Closing a non-UTF-8 file deleted its symbols.                                                                                 | A file with one Latin-1 byte was indexed at startup, then lost every symbol once closed or changed on disk.                                                                                                                                                                | The close and watcher reads decode loosely (`String::from_utf8_lossy`), as the scan already did.                                                                                                                                                                                                                                                 | `closing_a_non_utf8_file_restores_its_disk_symbols`.                                                                                                            |
| The scan's cancellation guarded against a second scan that never runs.                                                        | Nothing visible; about 50 lines of locking for a case nothing can trigger.                                                                                                                                                                                                 | One stop flag, set only by `shutdown`. The unused `ServerState::shutdown` field was removed. Only `initialized` starts a scan; an in-process rescan would need a per-scan flag again.                                                                                                                                                            | Existing scan and shutdown tests.                                                                                                                               |
| An older scan never stopped, open buffers were replaced by disk content, and the watcher indexed files outside the workspace. | Stale symbols, lost buffer edits, and symbols from sibling folders such as `/repo-other`.                                                                                                                                                                                  | Commit `bb695d1`: per-scan cancel token, buffer-owned index entries with revision checks and per-path disk tickets, and workspace checks by path component with symlinks ignored.                                                                                                                                                                | 28 tests in `src/backend/sync_tests.rs`; 9 checks in `e2e_lsp.py`.                                                                                              |
