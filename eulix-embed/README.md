# Eulix Embed (`eulix_embed`)

`eulix_embed` is the high-performance embedding engine for the Eulix code intelligence platform. It ingests the structured Knowledge Base (`kb.json`) generated by `eulix_parser`, segments code into semantic chunks, generates dense vector representations using Transformer models, and builds memory-mapped binary vector indices (`embeddings.bin` and `vectors.bin`) for instant retrieval.

---

## Features

- **Dual Inference Engines**:
  - **ONNX Runtime (`--engine onnx`)**: Lightweight, high-throughput inference with zero PyTorch overhead and native CPU/CUDA execution.
  - **PyTorch (`--engine torch`)**: Full PyTorch backend supporting CUDA, ROCm/HIP (AMD), and Apple Silicon (MPS).
- **Persistent Daemon Mode (`server`)**:
  - Eliminates model reload latency. Runs as a long-lived stdin/stdout daemon communicating with the Go CLI orchestrator for sub-50ms query embedding.
- **Fast Single-Pass Streaming**:
  - Employs `ijson` with C-extensions (`libyajl2`) and `orjson` to stream multi-gigabyte knowledge base JSON files with minimal memory overhead.
- **SQ8 int8 Vector Quantization**:
  - Optional `--quantize` flag compresses embeddings by 4× with negligible (<1%) retrieval quality degradation.
- **Intelligent Token Bucketing**:
  - Groups code chunks by sequence length prior to batching on GPU/CPU, eliminating padding overhead and dramatically boosting tokens/sec throughput.
- **Code Filtering**:
  - Optional `--no-comments` flag strips comments, docstrings, and license headers prior to embedding, focusing semantic space on actual logic.

## Installation & Setup

Recommend setting up `eulix_embed` using [uv](https://github.com/astral-sh/uv).

### 1. Environment Setup

```bash
cd eulix-embed

# Create virtual environment with Python 3.11
uv venv --python 3.11
source .venv/bin/activate   # On Windows: .venv\Scripts\activate
```

### 2. Install Dependencies

Depending on your preferred inference engine:

#### ONNX Runtime (Default & Recommended for CPU/CUDA)

```bash
uv pip install -r requiremenents/onnx-nvidia.txt
```

#### ONNX Runtime with ROCm

```bash
uv pip install -r requiremenents/onnx-amd.txt
```

#### PyTorch Backend

```bash
uv pip install -r requiremenents/torch-nvidia.txt # needs cuda 13.0 for any other version of torch check the pytorch's website
# torch for amd gpus
uv pip install -r requiremenents/torch-amd.txt
```

> **Tip (Fast JSON)**: Install `libyajl2` (`sudo apt install libyajl2` on Ubuntu/Debian) for 10× faster JSON parsing via `ijson`'s C-backend.

## CLI Usage

```text
python main.py <command> [options]
```

### 1. `embed` — Generate Embeddings for a Knowledge Base

```bash
uv run main.py embed \
  --kb-path .eulix/kb.json \
  --output .eulix \
  --model BAAI/bge-base-en-v1.5 \
  --engine onnx \
  --device auto
```

| Flag                    | Default                                  | Description                                          |
| ----------------------- | ---------------------------------------- | ---------------------------------------------------- |
| `-k, --kb-path <PATH>`  | `knowledge_base.json`                    | Path to the input knowledge base JSON.               |
| `-o, --output <DIR>`    | `./embeddings`                           | Directory where binary vector files will be written. |
| `-m, --model <NAME>`    | `sentence-transformers/all-MiniLM-L6-v2` | HuggingFace model name.                              |
| `-e, --engine <ENGINE>` | `onnx`                                   | Inference engine: `onnx` or `torch`.                 |
| `-d, --device <DEVICE>` | `auto`                                   | Execution device: `cuda`, `mps`, or `cpu`.           |
| `-b, --batch-size <N>`  | auto                                     | Batch size (defaults to 64 for GPU, 16 for CPU).     |
| `--max-chunk <N>`       | `2000`                                   | Maximum character limit per code chunk.              |
| `--quantize`            | off                                      | Enable SQ8 int8 quantization (4× storage savings).   |

---

### 2. `query` — Single-Shot Query Embedding

Embeds a query string from the command line, printing vector dimensions or raw JSON.

```bash
uv run main.py query \
  -q "how does authentication middleware work" \
  -m BAAI/bge-base-en-v1.5 \
  --engine onnx
```

| Flag                    | Default                                  | Description                        |
| ----------------------- | ---------------------------------------- | ---------------------------------- |
| `-q, --query <TEXT>`    | _(Required)_                             | Query string to embed.             |
| `-m, --model <NAME>`    | `sentence-transformers/all-MiniLM-L6-v2` | HuggingFace model name.            |
| `-e, --engine <ENGINE>` | `onnx`                                   | `onnx` or `torch`.                 |
| `-f, --format <FMT>`    | `json`                                   | Output format: `json` or `binary`. |

---

### 3. `server` — Persistent Stdin/Stdout Daemon

Runs a persistent embedding server used by `eulix chat` to embed queries interactively without process re-initialization.

```bash
uv run main.py server \
  -m BAAI/bge-base-en-v1.5 \
  --engine onnx \
  --device auto
```

---

### 4. `compare` — Validate Output Consistency

Verifies entry counts, dimensions, and spot-checks vector values between `embeddings.bin` and `vectors.bin`.

```bash
uv run main.py compare .eulix/embeddings.bin .eulix/vectors.bin
```

## Output Files

| File              | Description                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `embeddings.bin`  | Ordered binary list of `(id, vector)` entries preserving chunk ordering for sequential scans.               |
| `vectors.bin`     | Keyed lookup table mapping `symbol_id → vector_offset` for $O(1)$ direct vector access via `mmap`.          |
| `embeddings.json` | _(Optional, `--save-json`)_ Formatted JSON containing chunks, tokens, and vector coordinates for debugging. |

### Binary Format Specification

```text
Header:
  magic (4 bytes)          : "EULX"
  version (4 bytes)        : u32 little-endian
  model_name_len (4 bytes) : u32
  model_name (N bytes)     : UTF-8 string
  entry_count (4 bytes)    : u32
  dimension (4 bytes)      : u32

Payload (Repeated `entry_count` times):
  id_len (4 bytes)         : u32
  id_bytes (M bytes)       : UTF-8 string
  vector (dim * 4 bytes)   : f32 array (or int8 if --quantize)
```

## Recommended Models

| Model                                    | Dimension | Speed     | Best For                                                    |
| ---------------------------------------- | --------- | --------- | ----------------------------------------------------------- |
| `BAAI/bge-base-en-v1.5`                  | 768       | Fast      | **Recommended default**: Superior semantic code retrieval.  |
| `BAAI/bge-small-en-v1.5`                 | 384       | Very Fast | Resource-constrained environments and quick local indexing. |
